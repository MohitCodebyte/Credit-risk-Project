Step-by-Step Workflow

How The System Processes Credit Risk

Every stage has a specific purpose, from preparing the input data to generating the final prediction.

01 Data Foundation

Data Collection

Bank-level banking information provides external risk context, while the borrower dataset contains the individual-level attributes required for predictive modeling.

RBI Data CSV Pandas
02 Data Quality

Data Cleaning & Validation

Raw banking data is cleaned and validated by handling empty rows, standardizing columns, checking duplicate records, validating data types and checking numerical ranges.

Missing Values Duplicates Validation
03 Exploration

Exploratory Data Analysis

Borrower characteristics are explored to understand distributions, relationships, default patterns, outliers and potential risk drivers before model training.

Distribution Correlation Outliers
04 Feature Design

Feature Engineering

Additional analytical features are derived from existing borrower information, including EMI-to-income ratio, total debt exposure, credit-history-to-age ratio and delinquency indicators.

Ratios Derived Features Indicators
05 Imbalance Handling

SMOTE

Because default cases are less frequent than non-default cases, SMOTE is applied only to the training data to create a more balanced learning environment.

SMOTE Training Data Imbalanced-learn
06 Machine Learning

Model Training

Multiple classification algorithms are evaluated, including Logistic Regression, Random Forest, XGBoost and LightGBM.

Logistic Regression XGBoost LightGBM
07 Model Selection

Evaluation & Thresholding

Models are evaluated using classification metrics such as ROC-AUC, PR-AUC, precision, recall and F1-score. A probability threshold is selected for the final classification step.

ROC-AUC PR-AUC F1
08 Explainability

SHAP Analysis

SHAP is used to inspect feature contributions and understand which model inputs are associated with increasing or decreasing the model output.

SHAP Feature Importance Explainability
09 Risk Transformation

Risk Score Generation

The predicted default probability is converted into a 0–100 risk score. The score is then mapped to Low, Medium, High and Very High risk categories.

0–100 Score Risk Categories
10 Application

Flask Deployment Layer

The trained model and scoring configuration are loaded by Flask, allowing users to submit borrower information through a web interface and receive the model-generated risk output.

Flask Joblib HTML/CSS/JS
Feature Engineering

Turning Raw Attributes Into Useful Signals

Derived features provide additional information about borrower financial exposure and repayment behavior.

Engineered Credit Features

Feature engineering creates additional numerical signals from the original borrower attributes. These features are calculated consistently during both model training and live prediction.

EMI / Income Monthly EMI divided by monthly income.
Total Debt Exposure Existing debt plus requested loan amount.
Credit History Age Credit history years relative to borrower age.
Delinquency Flag Indicates whether previous delinquencies exist.

Evaluation Framework

Because the project contains fewer default cases than non-default cases, model evaluation considers more than accuracy alone. Ranking and minority-class performance are also examined.
